## Rules this order follows

* **Rand order first.** Parity is checked by the main thread's CRT sequence, so a slice that draws must land after every draw before it. The remaining draws, in order: 24 (Stats menu, first drain pass), 108 (the 11 actors' animation setup), 24 (the player's), 6 (the camera block, 1 attributed), the Sky's 59 (ported), 10 (loading menu close), 11 (race menu), 11 (movie).
* **Few builds.** Each build below is one compile and one focused test run, with a large slice behind it. Captures need no build, so they're batched into debugger sessions and done while a build runs.
* **Bevy does the drawing and the sound.** The game's logic is ported as data; the host turns it into Bevy work. That's already true for the interface (`Camera2d`, `Material2d` meshes, `GammaMaterial` for D3D9's blending), audio (`bevy_audio`) and movies. The world follows the same rule (Track R).

## Havok: Avian behind a seam (decided 2026-11-07)

The original's player ends 6.46 lower than its marker (z -108.06 against -101.598) because Havok's character controller falls to the floor inside `0065AF30`'s loop. The port has the bhk loaders but no `hkpWorld`. **Decision: Havok is a recorded host substitution, with [Avian](https://github.com/avianphysics/avian) 0.8 (Bevy 0.20) as the host's physics.** `avian3d` is a dependency of `recomp_host` (f32, `parry-f32`, `enhanced-determinism`), unused until Build 3.

* The game keeps Havok's callers and calls a physics seam at the original's sites: the cell's world built in `004D63A0`, the step at `004D4970` (with `00889810`'s substeps), the character controller's moves (`0065AF30`, `0065B5C0`), and ray casts. The host implements the seam with Avian on the same World, running its schedule and queries synchronously at those calls rather than in `FixedPostUpdate`.
* Shapes come from the port's loaded bhk data: MOPP and packed strips as triangle meshes, convex vertices as hulls, boxes and capsules directly, list and transform shapes as compounds, in Havok's units (the 0.1428767 scale).
* The character controller is a capsule moved with Avian's `MoveAndSlide`, with the original controller's state logic ported on top.
* Positions are checked against the captures with a tolerance, not bit for bit. No rand draw comes from Havok in any run, so the draw sequence stays exact; later gameplay, where physics feeds AI and combat, can drift, which open-items records.
* Clutter bodies and ragdolls (the prison's dead creatures hold rag-doll data) come after Target A.
